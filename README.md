# Эфир (Ether)

Мессенджер-PWA без аккаунтов и без сервера, который хранит переписку. Сообщения, файлы и звонки идут **напрямую между устройствами** (WebRTC). Сигнальный сервер нужен только чтобы устройства нашли друг друга, чтобы временно подержать зашифрованное сообщение для офлайн-получателя и чтобы отправить push.

> Этот документ описывает то, что **делает код** на версии из файла `VERSION` (сейчас V.62.0.0). Он написан по исходникам, а не по старой документации. Места, которые не удалось подтвердить чтением кода, помечены словом «не проверено».

## Архитектура

- **Клиент:** статическое одностраничное приложение на чистом JavaScript без сборки. Скрипты подключаются в `index.html` по порядку и делят глобальные имена: `app.js` (основное приложение), `group-call.js`, `features.js`, `features2.js`. Рядом `webrtc.js` (P2P-соединения), `signaling-client.js`, `signaling-codec.js`, `crypto-helper.js`, `crypto-worker.js`, `file-limits.js`, `i18n.js`.
- **PWA:** `manifest.webmanifest`, service worker `sw.js` (оболочка кешируется, приложение работает офлайн, push-уведомления). Хостинг фронтенда: GitHub Pages из ветки `main` (в репозитории нет `.github/workflows`, сборку делает встроенный механизм Pages).
- **Сервер:** `signaling-server/` на Node.js (`ws`, `web-push`, `dotenv`). По умолчанию клиент подключается к `wss://ether-1-baqy.onrender.com`; адрес меняется в Настройках → Приватность.
- **Транспорт сообщений:** WebRTC data channel, когда собеседник онлайн. Если нет, то зашифрованный конверт через почтовый ящик сервера.
- **Хранение на устройстве:** `localStorage` (контакты, настройки, ключи, очередь отправки), IndexedDB `ether-db` (файлы и зеркало критичных ключей `CRITICAL_LS_KEYS`).

## Идентичность и шифрование

- **Идентификатор** `Store.myId` = SHA-256 от `"ether:" + нормализованный телефон/email` (hex). Телефон нормализуется до `+цифры` (7–15 цифр), email до нижнего регистра. Хэш **не солёный**, поэтому номера можно подобрать перебором. Сервер не проверяет, что номер принадлежит регистрирующемуся.
- **Анонимный профиль:** если поле телефона/email при регистрации пустое, идентификатор — случайный UUID. Такого человека можно добавить только по QR или по коду.
- **Ключи:** на устройстве создаётся пара ECDH P-256 (WebCrypto), публичный ключ рассылается через сервер вместе с присутствием.
- **Шифрование конвертов** (`crypto-helper.js`): общий ключ ECDH → AES-GCM-256, случайный IV 12 байт, формат `{iv, ct, v:1}`. Без AAD, без подписи отправителя и без forward secrecy (ключи статические).
- **Номер безопасности:** SHA-256 от отсортированных публичных ключей, 12 групп по 5 цифр.
- **P2P-трафик** идёт по DTLS-каналу WebRTC; поверх него отдельного шифрования нет.

## Контакты и подключение

- **По телефону/email:** добавляете контакт, когда оба онлайн на одном сервере, приложение само строит P2P-связь. Подключение откладывается на 800 мс, оффер создаёт сторона с меньшим `id` (разрешение «столкновений»). Зависшее подключение пересоздаётся через 30 с.
- **QR-код:** содержит `ether://add?id=<хэш>&name=<имя>`. Сканирование — камера плюс встроенный `jsQR` (не `BarcodeDetector`).
- **Вручную, без сервера:** код приглашения = `"1"` + флаг + base64url(gzip(JSON `{t, n, d, r}`)), максимум 8192 символа. Есть ссылка вида `…#c=<код>`. Двухшаговый обмен: приглашение → код ответа.
- **Ссылка-приглашение в группу:** `ether://group?gid=&ref=&rn=&gn=`.
- **Через общий контакт (relay):** один «прыжок» по уже открытому P2P-каналу (`relay-request`/`relay-deliver`…), повтор не чаще раза в 60 с. Параллельно с серверным путём.
- **Адресная книга:** кнопка есть только если браузер поддерживает `navigator.contacts.select`. Подставляет **только имя**, телефон/email добавить автоматически нельзя.
- **«Сейчас онлайн»:** список из присутствия сервера (без тех, кто уже в контактах). Сервер рассылает присутствие всем подключённым клиентам, флаг `visible` соблюдают клиенты. Видимость отключается в Настройках.
- **Повторные попытки:** после ответа сервера `unreachable` пауза 60 с, затем 5 мин, затем 30 мин. WebSocket переподключается с задержкой 1 с ×1,6 до 20 с. После падения ICE делается ICE restart.
- **Статусы:** в звонке, подключён, подключается, онлайн, «был(а) в сети …», офлайн. Показ присутствия и времени визита учитывает настройки собеседника (`privacy-pref`).
- **Удаление контакта:** очищает очередь, черновики, папки, отложенные сообщения; id попадает в `recentlyDeletedIds` на 7 дней, предложения связи от него игнорируются. Собеседнику ничего не сообщается.
- **Блокировка:** локальный флаг. Входящие сообщения, звонки и предложения связи игнорируются; серверные сообщения только подтверждаются как «доставлено». Собеседник не уведомляется.

## Сообщения

**Доставка** (`sendChatMessage` → `trySendOrQueue` → `flushOutboxItem`):
- если есть живой P2P-канал, сообщение уходит по нему; через 1,5 с, если подтверждения нет, дублируется через сервер (получатель отсеивает дубликаты по id);
- если P2P нет, сразу в зашифрованный ящик сервера;
- если публичный ключ собеседника неизвестен, сообщение ждёт ключа (`pendingNoKey`) и помечается ошибкой;
- очередь `outbox` хранится на устройстве (до 500 записей, до 7 дней), повтор каждые 15 с, пока подключён сервер; при запуске недоотправленные текстовые сообщения (до 24 ч, только 1:1) отправляются заново.

**Статусы:** pending → отправлено → доставлено → прочитано (или ошибка). «Прочитано» уходит, когда лента прокручена к низу. Если выключить квитанции, «прочитано» не отправляется.

**Действия с сообщением:**
- ответ (меню или свайп), копирование, перевод;
- редактирование (только свои текстовые, только 1:1);
- удаление «у себя» (везде) и «у всех» (только свои, только 1:1);
- пересылка (в личные чаты; из группы пересылка работает через выбор нескольких сообщений);
- реакции эмодзи (только 1:1);
- закрепление сообщения (одно на чат, **только локально**), избранное (локально), выбор нескольких сообщений.

**Навигация:** поиск в чате с подсветкой, поиск по списку чатов, глобальный поиск (чаты, сообщения, контакты, звонки, настройки), переход к дате, разделитель «Непрочитанные», упоминания `@имя` в группах (обычный текст, подсказка из участников).

**Прочее:**
- индикатор «печатает…» (только P2P и только 1:1);
- черновики отдельно для каждого чата;
- отложенная отправка (час, завтра утром, своё время; текст; отправляется только пока приложение открыто — не проверено, как часто срабатывает проверка);
- исчезающие сообщения (выключено / 1 ч / 1 день / 1 неделя; таймер ставит любая из сторон в карточке контакта, он симметричный, без согласия второй стороны; время считается от отправки, а не от прочтения);
- превью ссылок через сервер (сервер видит ссылку), простая разметка `**жирный**`, `*курсив*`, `` `код` ``;
- перевод через LibreTranslate-совместимый сервер (по умолчанию `https://libretranslate.com/translate`, текст уходит на него открытым);
- эмодзи: пикер с поиском, недавние, тона кожи (в том числе двойной для 🤝/🫶), автозамена `:)` и подобных при отправке;
- «Сохранённые сообщения» — чат с самим собой, никуда не отправляется;
- карточка контакта (`contact-card`) пересылается другому человеку с кнопкой «Добавить»;
- лимиты: 4000 символов на сообщение, 5000 сообщений на чат (старые обрезаются).

## Файлы, фото, голосовые

В личных чатах и в группах (в группах — не больше **1 МБ** на файл/голосовое: рассылается каждому участнику отдельной копией).

- Можно выбрать файл до **20 МБ**, но отправляется не больше **2 МБ**. Изображения больше 2 МБ сжимаются автоматически (JPEG, не более 1920 px); видео и остальные файлы не сжимаются и отклоняются.
- **Живая передача:** кусками по 48 КБ с контролем заполнения канала (порог 256 КБ, таймаут 30 с), приёмник держит до 20 передач, буфер живёт 3 минуты.
- **Если собеседник офлайн:** файл целиком (base64) уходит одним зашифрованным конвертом через ящик сервера (хранение 48 часов).
- Файлы хранятся в IndexedDB; в переписке остаются только метаданные. Резервная копия **не содержит файлов**.
- **Голосовые:** запись через `MediaRecorder`, записи короче 0,6 с отбрасываются, проигрыватель с волной. Подтверждение «доставлено/прочитано» для файлов не приходит: статус остаётся «отправлено» (не проверено до конца).
- Фото можно отправить с подписью до 200 символов. Кнопка «+» в поле ввода — постоянная и анимированная (превращается в «×»): по нажатию выезжают три круга — эмодзи, камера (снять фото/видео сейчас), скрепка (фото/видео/документ с устройства). Поле ввода одинаково в личных чатах и группах.

## Групповые чаты

- Mesh: каждый участник соединён напрямую с каждым. Сообщение рассылается отдельной копией каждому (со своим `deliveryId`), доставка офлайн-участникам — через ящик сервера. **Максимум 10 участников.**
- Создатель (`createdBy`) и назначенные админы могут: менять название, аватар (160 px JPEG), описание (до 200 символов), добавлять и исключать участников, назначать и снимать админов (создателя снять нельзя), включать режим «писать могут только админы», получать ссылку-приглашение (QR и код).
- Режим «только админы» проверяется и при приёме. «Медленного режима» нет.
- Состав рассылается сообщением `group-invite`; он повторно отправляется при переподключении. Исключённый специального уведомления не получает.
- **В группах работают:** текст, ответы, упоминания, закрепление и избранное локально, перевод, поиск, черновики, отложенный текст, статусы доставки (по первому подтверждению любого получателя), TTL исчезающих сообщений при приёме, групповой звонок.
- **В группах не работают:** реакции, редактирование, удаление «у всех», индикатор набора, повторная отправка при запуске, пересылка через меню сообщения.

## Звонки

**Один на один** (`beginCall`, `webrtc.js`):
- голос и видео; видео можно включить в ходе звонка; переключение камеры (`replaceTrack`), показ экрана (`getDisplayMedia`), картинка-в-картинке, сворачивание звонка в полоску, mute, «принять без звука», громкость (GainNode), динамик/наушник (iOS — `navigator.audioSession`, остальные — `setSinkId`);
- индикатор качества по `getStats` каждые 3 с;
- сигнализация: `call-state` по P2P-каналу (`ringing`, `accepted`, `declined`, `ended`; пакеты старше 20 с игнорируются) и `call-invite` через сервер для пуша. Тайм-ауты: 20 с у звонящего, 18 с у принимающего;
- второй входящий получает «занято»;
- история звонков (до 500 записей), вкладка «Звонки», бейдж пропущенных, системная запись в чате;
- рингтоны: Classic, Soft, Bell; при выключенных звуках — только вибрация;
- экран не гаснет только во время видеозвонка (wake lock).

**Групповые** (`js/group-call.js`):
- до **6 участников**; mesh поверх уже установленных соединений группового чата (`PeerLink.addGroupTracks`), без relay-сервера;
- сигнализация `kind:"gcall"`: `invite`, `join`, `state` (mute/видео), `leave`, `full`; принимается только от участников группы, приглашения старше 30 с игнорируются;
- вход по баннеру «Войти / Не сейчас», плитки участников, mute, камера, выход, таймер;
- нужен хотя бы один участник онлайн; если вы уже в звонке, приглашения игнорируются, а входящий 1:1 получает «занято»;
- в конце в чат группы пишется системное сообщение с длительностью;
- **нет:** показа экрана, переключения камер, динамика/громкости, PiP, индикатора качества, записи в журнале звонков, пуша.

**Звонок офлайн-контакту:** кнопки звонка активны, если контакт онлайн или у него есть push-подписка. Сервер шлёт push (`call-invite`), по нажатию на уведомление приложение открывается на экране «входящий» и само поднимает P2P-соединение; приглашение досылается каждые 4 с, звонящий ждёт до 55 с. Принятие звонка ждёт установки P2P (до 25 с) и не сбрасывается, если соединения ещё нет.

**Сеть и обход блокировок UDP:** если ICE «подключился», а DTLS за 6 с не завершился (типично для фильтрации WebRTC у провайдеров), линк помечается relay-only на 30 минут: следующая попытка идёт только через TURN (по TCP/TLS), offer несёт `rl:1`, и собеседник отвечает так же. Для этого `TURN_STATIC_URL` на сервере может содержать несколько адресов (через запятую); к каждому `turn:` автоматически добавляется вариант `?transport=tcp` (лучше добавить и `turns:…:443`).

**Свой TURN на российском VPS.** Если оператор режет звонки через иностранные TURN (в Отладке «Проверить TURN» на телефоне без VPN: «allocation есть, но данные НЕ проходят», а на устройстве с VPN — работает), нужен TURN на российском IP. Скрипт `deploy/setup-coturn.sh` ставит coturn на Ubuntu/Debian, генерирует пароль и печатает три переменные (`TURN_STATIC_URL`, `TURN_STATIC_USERNAME`, `TURN_STATIC_PASSWORD`) для Render. Запуск: `sudo bash setup-coturn.sh [домен]` (домен — для TLS на 443, он выглядит как обычный HTTPS). Скрипт не проверялся на конкретных хостерах.

**Не работает:** голосовая почта.

## Уведомления и push

- Локальные уведомления показываются, только когда страница скрыта; настройка «скрывать текст» заменяет текст на «Новое сообщение».
- Web Push: подписка (`userVisibleOnly`, ключ VAPID берётся с сервера). Для звонка push уходит сразу при `call-invite` (срочность `high`, TTL 30 с). Для сообщений push уходит через 5 с, если конверт всё ещё не подтверждён (срочность `normal`, TTL 5 мин); не чаще раза в 30 с на отправителя, дальше объединяется в «N новых сообщений».
- Формат push: Declarative Web Push (`web_push: 8030`), текст сообщения в push **не** передаётся; подписи локализованы на 20 языков.
- Нажатие открывает чат или звонок (`?chat=`, `?call=`, обработка `handleNotificationNavigateParams`); в уведомлении есть действия «Ответить» и «Прочитано».
- Приём «Поделиться» из других приложений: manifest `share_target` (GET, `title`/`text`/`url`, без файлов) → выбор личного чата, текст кладётся в поле ввода, но **не отправляется сам**.
- Бейдж на иконке (`setAppBadge`), точка о пропущенных звонках.

## Приватность и безопасность

- Сервер не видит текст: в ящике лежит шифртекст; в логах и push нет содержимого. Сервер видит: хэш идентификатора, имя, публичный ключ, факт переписки и размеры, ссылки при запросе превью.
- **PIN-код на запуск:** только цифры, не менее 4, хранится как PBKDF2-SHA-256 (120 000 итераций, соль 16 байт). После 5 неверных попыток предлагается полный сброс, иначе блокировка (30 с × раунд, максимум 5 мин). **Это только экран-замок при холодном старте:** при уходе в фон повторной блокировки нет, а ключи и переписка в `localStorage` не шифруются.
- **Квитанции, «был(а) в сети», присутствие** отключаются в Настройках (действует по P2P, сервер присутствие всё равно видит).
- **Резервная копия:** экспорт всех ключей `ether.*` в JSON; по желанию с шифрованием паролем (PBKDF2-SHA-256, 210 000 итераций + AES-GCM). Без пароля файл открытый; если шифрование не удалось, копия сохраняется открытой. Файлы вложений в копию не входят.
- **Встряхнуть, чтобы стереть** (`panicShake`): сильная встряска → предупреждение на 4 с с возможностью отмены → полное стирание. Возможны ложные срабатывания. На iOS запрашивается разрешение на датчики.
- **Полное удаление:** `performFullAccountWipe` (localStorage, Cache Storage, IndexedDB). Пять нажатий на логотип в «О приложении» дают то же самое с подтверждением.
- **Dead man's switch (мягкий):** при открытии приложения отправляется «я жив» доверенному контакту (не чаще раза в 12 часов); получатель проверяет срок (3/7/14/30 дней) только при своём открытии приложения. Фонового таймера нет. Раздел находится во вкладке «Отладка».
- **Подписанный экспорт чата:** ECDSA P-256 + цепочка SHA-256 по сообщениям, проверка в Настройках. Закрытый ключ подписи лежит в `localStorage` (`ether.sigKey`) открытым JSON и попадает в зеркало IndexedDB.
- **Personal Sigil:** символ из ключа для сверки собеседника вживую.

## Настройки

Категории: Профиль, Приватность, Уведомления и безопасность, Оформление, Данные и резервные копии, Помощь и о приложении. Сверху закреплено поле поиска по настройкам.

- **Профиль:** имя, телефон/email (смена **меняет ваш id**, и контакты вас потеряют), «О себе» (до 80 символов, рассылается по P2P).
- **Приватность:** адрес сигнального сервера, подсказка про свой сервер, «Показывать в «Сейчас онлайн»», квитанции, «был(а) в сети», присутствие.
- **Уведомления и безопасность:** список заблокированных, уведомления, скрывать текст, превью ссылок, сервер и ключ перевода, звуки, рингтон с прослушиванием, PIN, «Встряхнуть для стирания».
- **Оформление:** тема (светлая, тёмная, OLED, системная), Calm mode, размер пузырей, размер шрифта, обои чата (нет, точки, сетка, градиент), автозамена эмодзи, экспериментальная кнопка «+», группы «Эффекты» и «Ещё эффекты».
- **Данные:** избранные сообщения, экспорт/импорт резервной копии, удаление данных.
- **Помощь:** справка (9 разделов), язык.
- **Вкладка «Отладка»** скрыта по умолчанию; открывается пятью нажатиями на заголовок. Содержит: dead man's switch, прозрачность «стекла», диагностику (в том числе блок `--- viewport ---`), состояние WebRTC, журнал событий (последние 300 из 500), хранилище и очистку старых медиа, экспорт диагностики, сброс соединений (кнопка «Drop all connections» на деле очищает ещё и контакты — см. «Известные проблемы») и полный сброс.
- **Зеркало IndexedDB:** критичные ключи копируются в IndexedDB через 1,5 с после изменения и восстанавливаются, если пропали из `localStorage`. В зеркало **не** входят: адрес сервера, переключатели приватности, обои, размеры, Calm mode, автозамена эмодзи, «О себе», отложенные сообщения.
- **Регистрация:** 4 слайда (язык, имя и необязательный телефон/email, аватар, готово с QR); импорт копии доступен прямо с экрана регистрации.

## Слой эффектов

Настройки хранятся одним JSON в `localStorage["ether.fx"]`; включаются в Настройки → Оформление → «Эффекты» и «Ещё эффекты». Всё локально, кроме отмеченного.

**Звук:** Sonic Signature (индивидуальный звук контакта, выкл.), тема контакта на ~3 с при открытии чата (выкл.), ambient-слой — тихий шум и редкие колокольчики, только в приложении (выкл.).

**Вид чата:** кристалл-«сейф» у заголовка (рост по числу сообщений), Patina (старше 90/365/730 дней), Bubble Dance (сообщения с разницей ≤500 мс), «дыхание» фона (по умолчанию выкл. на iOS; отключается при reduced-motion, скрытой вкладке, заряде <20%), сезонный оттенок (по календарю, смена за 3 дня), мягкий скин контакта (оттенок, форма пузырей, шрифт — выкл.), занавес при входе в чат, яркое кольцо аватара активного контакта, стиль голосовых «кассета/пластинка».

**События:** день рождения контакта (искры, конфетти при поздравлении), прощальная волна 👋, ритуал первого открытия за день, «Закрыть день» (после 22:00/до 04:00 при бездействии 90 с или кнопкой), сцена в пустом чате, пасхалки (🚀, тройной тап), Farewell Fade при удалении контакта, режимы сгорания исчезающих сообщений (затухание / пепел).

**Итоги и экспорт:** Yearly Wrapped, постер переписки (PNG 1080×1350), Replay месяца (видео WebM, запись на устройстве), стена Time Capsule (открытки из избранного), подписанный экспорт.

**Новое взаимодействие:**
- *Созвездие* — вид списка контактов в виде звёзд (до 60, без связей между контактами);
- *мини-треды реакций* — нажатие на реакцию открывает ответы, привязанные к ней (обычные ответы с невидимой меткой, протокол не менялся);
- *усиленная реакция* — долгое нажатие на эмодзи, серия вспышек (видна только отправителю);
- *рисование на видео* — в активном 1:1-звонке, по согласию обеих сторон; штрихи тают за 5 с и не сохраняются; сообщения `fxdraw`;
- *Vision Loop* — 3-секундный «взгляд» тыловой камерой: около 9 JPEG-кадров 180×240, нужно включить приём у обеих сторон (по умолчанию выкл.), оба видят индикатор «камера открыта», ничего не сохраняется; сообщения `fxlook`;
- *Костёр* — временная группа по QR на 4 часа; срок хранится в описании группы, **удаление выполняет каждый клиент у себя**, участники остаются в контактах.

**Опциональное:**
- цвета по погоде — **единственное обращение к третьей стороне**: после явного согласия приблизительные координаты (до 0,1°) отправляются на `api.open-meteo.com`, сохраняется только тип неба на 3 часа;
- краевой пульс при новом сообщении (только при открытом приложении);
- хаптика (только Android);
- акцент «Аврора» — косметика, открывается при принятии приглашения в группу или когда кто-то вошёл по вашему приглашению;
- Call Film — сводка после группового звонка (длительность, участники, число сообщений).

## Сигнальный сервер

`signaling-server/server.js` (Node ≥ 18; зависимости `ws`, `web-push`, `dotenv`).

**HTTP:**
- `GET /health` и `/` — «Ether signaling relay OK»;
- `GET /ice` — список ICE-серверов (лимит 20 запросов в минуту на IP, кеш 5 мин). Если заданы `TURN_STATIC_*`, отдаётся статический TURN (доступность проверяется TCP-подключением) плюс STUN Google; иначе только STUN Google. Ключи не временные;
- `GET /link-preview?url=` — лимит 30/мин на IP; только http/https; DNS резолвится один раз и адрес фиксируется, приватные и служебные адреса блокируются, до 3 редиректов с проверкой каждого, только `text/html`, не более 512 КБ, таймаут 6 с; кеш 1 час; при любой ошибке — `204`.

**WebSocket** (кадр до 8 МиБ): `register`, `ping`, `signal` (пересылка онлайн-получателю, не хранится; `call-invite` дополнительно вызывает push), `deliver` (конверт; **всегда** кладётся в ящик получателя и сразу отправляется, если он онлайн), `mailbox-ack`, `push-subscribe`/`push-unsubscribe`. Лимиты: регистрация 15/мин на IP, `signal` 120/мин, `deliver` 60/мин на пару; клиент шлёт ping каждые 15 с, сервер сам ping каждые 30 с.

**Что где хранится:** в памяти — подключённые клиенты, почтовые ящики, счётчики лимитов, кеши. На диске — **только** подписки push (`.ether-push-subs.json`). При перезапуске сервера ящики теряются; на бесплатном Render диск, вероятно, не переживает передеплой (не проверено).
- Ящик: до 500 записей на пользователя (старейшие вытесняются); конверты не-чатов (файлы, голос) живут 48 часов; текстовые конверты по времени **не** истекают, удаляются подтверждением `mailbox-ack`.
- Push включается только при наличии `VAPID_PUBLIC` и `VAPID_PRIVATE`.

**Переменные окружения:** `PORT` (8787), `ALLOWED_ORIGIN` (по умолчанию `*`), `APP_BASE_URL`, `VAPID_PUBLIC`, `VAPID_PRIVATE`, `VAPID_SUBJECT`, `TURN_STATIC_URL`, `TURN_STATIC_USERNAME`, `TURN_STATIC_PASSWORD`, `CF_TURN_KEY_ID` + `CF_TURN_API_TOKEN` (Cloudflare Realtime TURN: бесплатный тариф, временные креды запрашиваются по API и кэшируются на сутки; идёт первым в `/ice`, адреса 443/80 по TCP/TLS; Cloudflare → Realtime → TURN → Create), `TURN_EXTRA_JSON` (запасной TURN-провайдер: JSON-массив — или готовый JS-фрагмент из панели провайдера, например «Show ICE Servers Array» у Metered: сервер сам вынет из него массив `[{"urls":["turns:host:443?transport=tcp"],"username":"…","credential":"…"}]`), `TURN_CHECK_DISABLED`. Ключи VAPID: `npm run generate-vapid`.

**Запуск:** `render.yaml` (Blueprint для Render: корень `signaling-server`, `npm install --omit=dev`, `node server.js`, проверка `/health`, автодеплой), `Dockerfile`, `docker-compose.yml`, подробности в `signaling-server/SELF_HOSTING.md`. На бесплатных тарифах сервер «засыпает» без обращений, первое подключение после паузы занимает до ~30 с.

## Разработка, тесты, версии, деплой

- **Клиентские тесты:** `cd tests && npm install && npm test` (jsdom + `fake-indexeddb` + реальный WebRTC через `@roamhq/wrtc`; профили iOS, Android, десктоп). Сейчас 212 тестов, весь прогон занимает несколько минут. Покрытие: `npm run coverage` (c8).
- **Тесты сервера:** `cd signaling-server && npm test` (цепочка скриптов `test-*.js`: два клиента, WebRTC, шифрование, ссылочное превью, файлы, видеозвонок, relay и др.).
- **Версии:** файл `VERSION`, `APP_VERSION` в `js/app.js` и `CACHE_VERSION` в `sw.js` поднимаются вместе. Правило: мелкие правки и документация — второе число (`V.X.Y → V.X.(Y+1)`), новые функции и крупные переделки — первое (`V.X.Y → V.(X+1).0`).
- **Деплой:** фронтенд — публикация ветки `main` на GitHub Pages; сервер — Render (автодеплой по `render.yaml`). Новый service worker не активируется сам: клиент ждёт сообщения `SKIP_WAITING` от страницы.

## Ограничения и известные проблемы

- Голосовой почты нет. Звонок офлайн-контакту идёт через push и ждёт, пока тот откроет приложение; на iOS это не гарантия. Первый коннект к бесплатному серверу Render после простоя может занимать 10–30 с (`.github/workflows/keep-signaling-awake.yml` пингует `/health` каждые 10 минут, но срабатывает только из `main`).
- Групповой звонок ограничен 6 участниками и без показа экрана, динамика и PiP.
- Групповой звонок включает wake lock даже для аудио (в 1:1 он только для видео).
- **Безопасность:**
  - обработчик `group-invite` не проверяет, что отправитель — админ группы: любой участник может изменить состав, название, аватар и описание;
  - хэш идентификатора не солёный, владение номером не проверяется;
  - PIN — только экран-замок при холодном старте;
  - закрытый ключ подписи экспорта лежит в `localStorage` открытым;
  - шифрование — статический ECDH без forward secrecy и без аутентификации отправителя;
  - TURN-доступ выдаётся статическими, не временными учётными данными.
- Погодный оттенок после трёх часов гаснет и сам не обновляется.
- Кнопка отладки «Drop all connections» очищает также контакты, чаты, журнал звонков и очередь; подтверждение сформулировано как удаление контакта.
- Поле «Сервер перевода» в Настройках описано как «пусто по умолчанию», но в коде по умолчанию стоит `libretranslate.com`.
- В тексте справки внутри приложения сказано, что файлы доставляются только онлайн; по коду файл до 2 МБ доходит и офлайн через ящик сервера.
- Не проверено: срабатывание отложенных сообщений при закрытом приложении (проверка идёт, пока приложение открыто), поведение групповых таймеров исчезновения (кнопка выбора таймера в группе, возможно, не доводит значение до участников), доступность TURN на сервере по умолчанию.
