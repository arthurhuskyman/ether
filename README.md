
## Новое: подключение по номеру/email без ручного обмена кодами

Теперь в приложении два способа связаться с кем-то:

1. **Через сигнальный сервер (по умолчанию, рекомендуется).** Вы добавляете
   контакт по телефону или email во вкладке «Контакты» — без всякого кода.
   Как только оба устройства одновременно открыты и подключены к одному и
   тому же сигнальному серверу, приложение само устанавливает P2P-связь.
   Сервер участвует только в этом «рандеву»: он держит в памяти (не на
   диске) список «кто сейчас онлайн» по хэшу от номера/email и один раз
   пересылает технический пакет offer/answer. Сама переписка и звук по-
   прежнему идут строго напрямую между устройствами.
2. **Полностью без сервера, по коду** — старый способ никуда не делся,
   он теперь во вкладке «Контакты» под ссылкой «Ручное подключение без
   сервера, по коду».

### Как развернуть свой сигнальный сервер (бесплатно)

Код сервера — в папке `signaling-server/`. **Важно, это уже не «просто
релей»** — сервер сейчас делает три вещи:

1. **Рандеву и почтовый ящик** — как и раньше, только в памяти процесса,
   ничего не пишет на диск.
2. **Web Push** — чтобы уведомлять о сообщениях/звонках, когда приложение
   закрыто. Для этого сервер **хранит список push-подписок в файле
   `.ether-push-subs.json` на диске** (не в памяти) — это осознанное
   исключение из принципа «ничего не на диске»: подписки должны
   переживать перезапуск сервера, иначе push переставал бы работать
   при каждом рестарте/деплое.
3. **Прокси для TURN (Metered)** — эндпоинт `GET /ice` отдаёт клиенту
   TURN-credentials, полученные от Metered по серверному API-ключу
   (ключ клиенту никогда не передаётся).
никакой базы данных, ничего не пишет на диск.

1. Зарегистрируйтесь на **render.com** (есть бесплатный тариф) — или
   на Railway/Fly.io, шаги аналогичные.
2. New → Web Service → загрузите (или подключите через GitHub) папку
   `signaling-server`.
3. Build command: `npm install`. Start command: `npm start`.
4. После деплоя Render даст адрес вида `https://ваш-сервис.onrender.com`.
   В приложении, в Настройках → «Сигнальный сервер», укажите его как
   `wss://ваш-сервис.onrender.com` (именно `wss://`, не `https://`).
5. У всех, кто должен находить друг друга автоматически, должен быть
   указан **один и тот же** адрес сервера.

Бесплатные тарифы таких хостингов обычно «засыпают» после нескольких
минут без обращений и просыпаются секунд за 20–30 при следующем
подключении — это нормально, просто первое соединение после паузы
будет чуть медленнее.

### Важная оговорка о приватности

Приложение отправляет на сервер не сам номер/email, а их хэш (SHA-256),
посчитанный на устройстве. Но пространство телефонных номеров
небольшое, поэтому хэш от номера в теории можно подобрать перебором —
это не полная анонимность, а лишь то, что сервер не хранит номера в
явном виде. Для более чувствительных контактов используйте ручное
подключение по коду, где сервер не участвует вообще.

Сервер также не проверяет, что регистрирующийся с конкретным id
действительно владеет этим номером/почтой — знания номера достаточно,
чтобы зарегистрироваться под ним и получать адресованные ему
уведомления. Для круга доверенных контактов это не проблема; для
публичного продукта нужна отдельная верификация (SMS/email-код), её
пока нет.

Push-уведомления добавляют ещё один нюанс: чтобы уведомить о сообщении,
когда приложение закрыто, сервер должен временно знать, что вам вообще
что-то пришло — сам текст сообщения он по-прежнему не видит (пуш несёт
только имя отправителя и общую подпись вида «Новое сообщение»), но факт
переписки и её участников — да, в момент отправки push. Если это для
вас критично — push можно отключить в Настройках, тогда работает только
как раньше: сообщение ждёт, пока вы сами откроете приложение.

## Гарантированная доставка офлайн-сообщений и статусы (галочки)

Раньше сообщение можно было отправить только пока собеседник тоже
онлайн — иначе оно просто не уходило. Теперь это не так:

- Пока оба устройства онлайн одновременно — сообщение, как и раньше,
  идёт напрямую по WebRTC data channel, сервер его вообще не видит.
- Если собеседник офлайн — сообщение **шифруется прямо на устройстве**
  (ECDH P-256 + AES-GCM, реализация в `js/crypto-helper.js`) общим
  ключом, который знают только два устройства, и в таком виде
  временно кладётся на сигнальный сервер. Сервер хранит только
  нечитаемый шифротекст в памяти (не на диске) до тех пор, пока
  собеседник не подключится и не заберёт его — после чего запись
  удаляется.
- Ключевая пара генерируется один раз на устройстве при первом
  запуске; секретный ключ никуда не отправляется, публичный —
  объявляется через сигнальный сервер вместе с присутствием (это не
  более чувствительно, чем открытый номер в адресной книге).
- Если получателя вообще никогда не видели онлайн (и поэтому не знают
  его публичный ключ) — сообщение не может быть зашифровано и
  помечается красной галочкой; как только контакт хотя бы раз
  появится в сети, накопившиеся такие сообщения уйдут автоматически.

**Статусы (галочка у своего сообщения):**
- ⚪ Серая — отправлено (ушло с устройства).
- 🟡 Жёлтая — доставлено: либо собеседник получил его напрямую, либо
  сервер гарантированно принял его на хранение.
- 🟢 Зелёная — собеседник открыл переписку и увидел сообщение.
- 🔴 Красная — не удалось даже связаться с сервером (нет сети и т.п.);
  повторная отправка произойдёт автоматически при восстановлении связи.

Это касается только текстовых сообщений. Звонки по-прежнему работают
только «вживую» — оба устройства должны быть на связи одновременно,
гарантированной доставки пропущенного звонка нет.

### Что изменилось в этой версии (v1.0.1)

- Утечки памяти устранены: `pendingAcks`, `outbox`, `pendingNoKey` чистятся
  по `deliver-ack` и при удалении контакта.
- Недоотправленные сообщения восстанавливаются из хранилища при запуске
  и повторно отправляются при появлении связи (`resumeUnsentMessages`).
- Сообщения, ушедшие по P2P, но не подтверждённые за 3 секунды,
  дублируются через сервер (идемпотентно по `id`).
- Квитанции о прочтении батчатся (`ack-batch`) — одно шифрование на группу.
- Новый контакт не помечается ошибочно «в сети», если он офлайн.
- `force`-повтор автоподключения уважает тай-брейк по id.
- Квитанции о доставке/прочтении ставятся в очередь повторной отправки.
- Ограничение длины сообщения — 4000 символов.
- Сервер: `maxPayload` 128 КиБ, валидация конверта, graceful shutdown
  по SIGTERM/SIGINT, presence при замене сессии.
- CSS: `color-scheme`, фон в `data-theme="auto"` приглушается только
  при светлой системе.
- Service worker: не кеширует cross-origin и query-string.
