# Свой сервер signaling для Мессенджера

killer-features-backlog 0.2 — «свой сервер» как оформленная фича, не просто настройка.

Этот сервер **не видит содержимого сообщений** (сквозное шифрование ECDH + AES-GCM, см. корневой `README`/комментарии в `server.js`). Он знает только: кто онлайн, держит офлайн-почтовый ящик (TTL: текст 5 минут, файлы 48 часов), и — опционально — отправляет Web Push и отдаёт TURN-credentials. Разворачивая свой экземпляр, вы меняете не протокол, а то, кто оператор этой небольшой, не видящей сообщений инфраструктуры — это и есть позиционирование для юрфирм/клиник/команд, которым нужно «вендор не видит наш трафик» в письменном виде.

## Быстрый старт (Docker)

```bash
cd signaling-server
cp .env.example .env
# отредактируйте .env — минимум VAPID_* (см. ниже) и ALLOWED_ORIGIN/APP_BASE_URL
docker compose up -d
```

Сервер слушает на `PORT` (по умолчанию 8787) внутри контейнера, `docker-compose.yml` публикует тот же порт наружу.

## Без Docker

```bash
cd signaling-server
npm install
npm run generate-vapid   # один раз — выводит VAPID_PUBLIC/VAPID_PRIVATE для .env
cp .env.example .env     # и заполнить
npm start
```

Требуется Node.js ≥ 18 (см. `package.json` → `engines`).

## Обязательно для продакшена

1. **HTTPS/WSS** — сервер слушает обычный `ws://` (см. `server.js`, `http.createServer`), поставьте перед ним reverse-proxy с TLS (Caddy, nginx, Traefik) — браузеры не разрешат `wss://` страницу обращаться к незащищённому `ws://`.
2. **ALLOWED_ORIGIN** — без него `/ice` отдаёт TURN-credentials в ответ на запрос с любого сайта; укажите origin вашего фронтенда (без пути, без слэша на конце).
3. **VAPID** — без ключей push-уведомления о сообщениях при закрытом приложении не работают (приложение продолжит работать, просто без фонового пуша).
4. **TURN** (опционально) — без него работает только публичный STUN, что ненадёжно за строгим/симметричным NAT (частый случай мобильных сетей). Рекомендуется свой coturn с временными кредами (см. ниже). Статические `TURN_STATIC_USERNAME`/`TURN_STATIC_PASSWORD` (например, бесплатный ExpressTURN) остаются для совместимости, но это **устаревший способ**: пароль не истекает, а `/ice` раздаёт его любому.
5. **Хранилище** — задайте `DATA_DIR` на постоянный диск: там лежат почтовый ящик (`.ether-mailbox.json`) и claim-токены id (`.ether-claims.json`, права 0600). Без постоянного диска claim-ы теряются при каждом перезапуске, и защита id от захвата работает только до него. `CLAIM_TTL_HOURS` (по умолчанию 336 = 14 суток) — через сколько без владельца id можно занять заново.
   Там же — алиасы миграции id v1 → v2 (`.ether-aliases.json`, права 0600): `ALIAS_TTL_DAYS` (90), `ALIASES_MAX` (50000), `ALIASES_PERSIST=0` отключает запись на диск. Сервер объявляет feature `alias`; клиенты запускают перенос id только на серверах с ней. Сервер принимает оба вида id (`<64 hex>` и `v2:<64 hex>`). Пока алиас жив и владелец онлайн, claim старого id продлевается автоматически.
6. **TRUST_PROXY** — по умолчанию выключен: IP клиента берётся из TCP-соединения, заголовок `X-Forwarded-For` игнорируется (иначе при прямом подключении клиент подделкой заголовка обходит все лимиты по IP). Если сервер стоит за reverse-proxy (Caddy, nginx, Traefik, Render и т.п.), задайте `TRUST_PROXY=1` — тогда IP клиента берётся из ПОСЛЕДНЕЙ записи `X-Forwarded-For`, которую дописывает ваш прокси. Не включайте `TRUST_PROXY`, если порт сервера доступен напрямую, минуя прокси. Без него за прокси все клиенты выглядят как один IP и упираются в общие лимиты. В `docker-compose.yml` и `render.yaml` для этого есть готовая переменная.

## coturn с временными кредами (TURN REST API, `use-auth-secret`)

Сервер выдаёт клиентам `username = "<unix-время-истечения>:ether"` и `credential = base64(HMAC-SHA1(secret, username))`; coturn проверяет их тем же секретом, ничего не храня. Креды живут `TURN_TTL_SECONDS` (по умолчанию 24 ч), ответ `/ice` кешируется на 5 минут.

1. Сгенерируйте секрет: `openssl rand -hex 32`.
2. В `/etc/turnserver.conf`:
   ```
   use-auth-secret
   static-auth-secret=<тот же секрет>
   realm=turn.example.org
   fingerprint
   no-multicast-peers
   denied-peer-ip=10.0.0.0-10.255.255.255
   denied-peer-ip=172.16.0.0-172.31.255.255
   denied-peer-ip=192.168.0.0-192.168.255.255
   # для TLS на 443: cert=/etc/letsencrypt/live/<домен>/fullchain.pem  pkey=/etc/letsencrypt/live/<домен>/privkey.pem  tls-listening-port=443
   ```
   Строки `lt-cred-mech`/`user=` не нужны (и не должны сочетаться с `use-auth-secret`). Перезапустите coturn.
3. В `.env` сервера сигналинга: `TURN_STATIC_URL=turn:turn.example.org:3478` (можно несколько через запятую, к `turn:` автоматически добавляется `?transport=tcp`), `TURN_STATIC_SECRET=<секрет>`, при желании `TURN_TTL_SECONDS=86400`. `TURN_STATIC_USERNAME`/`PASSWORD` в этом режиме не используются — удалите их.
4. Проверка: `curl https://ваш-сервер/ice` должен вернуть `username` вида `1760000000:ether`; в приложении «Отладка → Проверить TURN».

Часы сервера сигналинга и coturn не обязаны совпадать точно: срок жизни — сутки, допуск большой.

## Подключение приложения к своему серверу

В Мессенджере: Settings → Signaling server → вставьте `wss://ваш-домен` → «Save and connect». Это уже существующая настройка (`Store.signalingUrl`) — весь смысл этого документа в том, чтобы разворачивание сервера было таким же простым, как сама настройка.

## Что сервер физически не может узнать

Содержимое сообщений, файлов и голосовых шифруется на устройствах до отправки — сервер передаёт только зашифрованный конверт (`envelope`) и открытое поле `kind` (нужно для решения, слать ли push). Подробнее — комментарий в начале `server.js`.
