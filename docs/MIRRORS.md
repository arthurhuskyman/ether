# Зеркала приложения («нельзя заблокировать»)

Приложение — обычные статические файлы. Любой человек может выложить копию на любой хостинг: у копии будет свой адрес (origin), а сервер-посредник в ней можно указать свой. Если основной адрес заблокирован, пользователи открывают зеркало, и все данные (контакты, ключи) на новом origin начинаются заново: переносите их через резервную копию или перенос на новое устройство.

## 1. Собрать зеркало

```
node tools/build-bundles.js            # бандлы должны быть актуальны
node tools/make-mirror.js --server wss://relay.example.org --mirror https://mirror.example.net/ether/ --out dist/mirror
```

Параметры: `--server` (можно несколько; первый = основной; встроенный сервер Ether добавляется после них, убрать: `--no-default`), `--label "имя"`, `--mirror` (известные адреса приложения, попадают в `config.js`), `--no-zip`, `--lock-connect` (сузить CSP `connect-src` до перечисленных серверов; включайте осознанно: пользователь не сможет добавить сторонний сервер, а `index.html` перестанет совпадать с подписанным релизом).

Результат: папка `dist/mirror` и архив `dist/mirror.zip`. Внутри те же файлы, что у основного сайта, и свой `config.js` (`window.__ETHER_CONFIG__ = {servers:[…], mirrors:[…]}`), плюс `_headers`, `.nojekyll`, `nginx.conf.example`, `mirrors.json`.

Почему это безопасно для разных origin: пути в `index.html`, `sw.js` и манифесте относительные, область service worker берётся от места файла, CSP опирается на `'self'` и разрешает `https:`/`wss:` (inline-скрипты разрешены по хэшам, они не зависят от адреса). Поэтому `index.html`, `sw.js` и бандлы копируются без изменений; меняется только `config.js`. Сервер должен разрешать ваш origin: на реле задайте `ALLOWED_ORIGIN=https://ваш-origin` (через запятую можно перечислить несколько origin, см. RELAY-OPERATOR.md); `/health` и `/info` отвечают любому origin.

## 2. Где разместить

Нужен HTTPS (без него service worker и камера не работают).

- **GitHub Pages (форк):** сделайте форк репозитория, положите содержимое `dist/mirror` в ветку, которую публикует Pages (или в `docs/`), включите Pages. Файл `.nojekyll` уже есть. Адрес вида `https://имя.github.io/репозиторий/` — работает из подпапки.
- **Cloudflare Pages:** «Create project» → «Direct upload», загрузите папку `dist/mirror` (или zip). Файл `_headers` применится сам. Бесплатного тарифа достаточно.
- **Netlify:** Sites → «Deploy manually», перетащите папку. `_headers` тоже подхватывается.
- **IPFS:** `ipfs add -r dist/mirror`, откройте через любой шлюз (`https://<cid>.ipfs.dweb.link/`) или свой домен с DNSLink. Адрес зависит от содержимого: новое зеркало = новый CID; закрепите (pin) у себя или в бесплатном сервисе закрепления.
- **Обычный nginx/Apache/Caddy:** скопируйте папку в корень сайта; пример заголовков в `nginx.conf.example` (`sw.js`, `index.html`, `config.js` без кэша; тип `application/manifest+json` для `.webmanifest`).
- Любой другой статический хостинг: достаточно отдавать файлы как есть по HTTPS.

Проверка после публикации: откройте адрес, в Настройках → Дополнительно → Серверы должны быть ваши серверы; кнопка «Проверить» покажет задержку.

## 3. Список зеркал `mirrors.json` и подпись

Чтобы пользователи могли узнавать новые адреса и не доверяли подделкам, список зеркал подписывается ключом релизов (ECDSA P-256, тот же, что у `js/release-key.js`):

```
# mirrors.json
{"v":1,"ts":0,"mirrors":[{"url":"https://mirror.example.net/ether/","label":"Мирор 1"}],"sig":""}

node tools/sign-list.js mirrors.json --field mirrors --private /безопасное/место/release-private.jwk.json
node tools/sign-list.js mirrors.json --field mirrors --verify  public.jwk.json      # проверка
```

Подписанный файл выкладывается рядом с приложением (`/mirrors.json`) и на любом другом адресе (gist, IPFS, другой домен). Формат подписи: ECDSA P-256 / SHA-256 в виде IEEE-P1363, base64url, по строке `ether-mirrors-v1\n<v>\n<ts>\n<url>\t<label>…` (то же для `servers.json` с полем `servers`). Приватный ключ хранится вне репозитория (docs/RELEASING.md). Без ключа в `js/release-key.js` приложение считает список непроверенным: показывает его, но сам не применяет.

Список серверов `servers.json` подписывается так же (`--field servers` по умолчанию) и подхватывается приложением автоматически, если подпись верна; вручную его можно загрузить из файла или по адресу в Настройки → Дополнительно → Серверы.

## 4. Как добавить своё зеркало в общий список

Откройте обращение в репозитории с адресом зеркала и подтверждением, что вы публикуете неизменённые файлы (`release-manifest.json` совпадает). Владелец релизов добавит адрес в подписанный `mirrors.json`.
