# Как запустить релей-сервер (для волонтёров)

Релей — небольшой Node.js-сервис (`signaling-server/server.js`): знакомит устройства, пересылает сигналы звонков и хранит зашифрованные конверты, пока адресат офлайн. Содержимое сообщений он прочитать не может. Чем больше независимых релеев, тем сложнее заблокировать сеть: клиент переключается между ними сам.

## Требования

Node.js 18+ (или Docker), 256 МБ ОЗУ, публичный адрес по HTTPS/WSS (сертификат даёт Caddy, Cloudflare, платформа хостинга). Платные сервисы не нужны: подойдёт бесплатный хостинг или ваш домашний/арендованный сервер.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `PORT` | порт HTTP/WebSocket (за прокси обычно 8787) |
| `ALLOWED_ORIGIN` | origin приложения для CORS: `https://имя.github.io`; несколько (приложение и зеркала) через запятую. `*` допустим только для проб; `/health` и `/info` всегда открыты |
| `APP_BASE_URL` | полный адрес приложения (с путём) для переходов из push |
| `DATA_DIR` | каталог данных (ящик, claim-токены, подписки). Нужен постоянный диск, иначе при перезапуске очередь теряется |
| `MAILBOX_FILE`, `CLAIMS_FILE`, `ALIASES_FILE`, `DEVICES_FILE`, `PUSH_SUBS_FILE` | пути отдельных файлов (по умолчанию внутри `DATA_DIR`) |
| `MAILBOX_PERSIST=0`, `CLAIMS_PERSIST=0` | не писать на диск (диск эфемерный) |
| `MAILBOX_MAX_PER_USER` | потолок очереди на получателя (по умолчанию 500) |
| `MAILBOX_PERSIST_MAX_BYTES` | потолок размера файла ящика (по умолчанию 150 МБ) |
| `TRUST_PROXY=1` | брать IP клиента из `X-Forwarded-For` (только за своим прокси) |
| `VAPID_PUBLIC`, `VAPID_PRIVATE`, `VAPID_SUBJECT` | ключи Web Push (`npm run generate-vapid`); без них push выключен, остальное работает |
| `PUSH_ACK_ORIGINS`, `PUSH_ACK_SECRET` | дополнительные origin для подтверждений push |
| `TURN_STATIC_URL/USERNAME/PASSWORD/SECRET`, `TURN_EXTRA_JSON`, `CF_TURN_*` | TURN для звонков (необязательно) |
| `DISCOVERY_ENABLED` | поиск по хэшу телефона/почты (по умолчанию выключен; включайте только осознанно) |

## Способы запуска

**docker-compose (VPS или домашний сервер):**
```
cd signaling-server && cp .env.example .env     # заполните значения
docker compose up -d                            # порт PORT, данные в ./data
```
Поставьте перед контейнером Caddy или nginx с HTTPS и `TRUST_PROXY=1`. Пример Caddy: `relay.example.org { reverse_proxy 127.0.0.1:8787 }`.

**Render (бесплатный тариф):** New → Blueprint, укажите репозиторий (файл `render.yaml` уже есть). Бесплатный сервис засыпает через 15 минут простоя и хранит данные на эфемерном диске: ящик не переживёт перезапуск, первое подключение после сна медленное. Для постоянных очередей нужен постоянный диск.

**VPS без Docker:** `cd signaling-server && npm ci --omit=dev && PORT=8787 DATA_DIR=/var/lib/ether ALLOWED_ORIGIN=https://… node server.js`, автозапуск через systemd (`Restart=always`, отдельный пользователь, `ProtectSystem=strict`, `ReadWritePaths=/var/lib/ether`).

## Рекомендуемые ограничения

- Один процесс, один экземпляр (состояние хранится в памяти и файлах).
- Диск под данные 1 ГБ, мониторинг свободного места.
- Лимиты в коде уже включены: размер сообщения 8 МБ, 500 конвертов на получателя, частота доставки и регистрации. Не поднимайте их без причины.
- Не логируйте содержимое запросов в прокси; сервер и так не видит открытый текст.
- Обновляйтесь вместе с репозиторием; версию и возможности видно по `GET /info`: `{"name":"ether-relay","version":"…","features":[…]}`.

## Проверка

```
curl https://relay.example.org/health      # ответ OK
curl https://relay.example.org/info        # JSON с version и features, заголовок Access-Control-Allow-Origin: *
```
В приложении: Настройки → Дополнительно → Серверы → ввести `wss://relay.example.org` → «Добавить» → «Проверить» (зелёная точка и задержка).

## Как попасть в общий список

Откройте обращение в репозитории: адрес `wss://…`, страна/хостинг (по желанию), контакт. Владелец проверит `/info`, задержку и доступность в течение нескольких дней и добавит сервер в подписанный `servers.json` (формат и подпись: docs/MIRRORS.md, `node tools/sign-list.js servers.json --private …`). После этого клиенты с проверенным ключом релизов получат его автоматически; остальные могут добавить адрес вручную. Если сервер надолго недоступен, его уберут из списка.

## Что видит оператор

Идентификаторы (случайные или производные от телефона/почты хэши), время подключения, IP-адрес на время соединения, размеры зашифрованных конвертов. Тексты и файлы зашифрованы между устройствами. Подробности: docs/PRIVACY.md, docs/THREAT-MODEL.md.
