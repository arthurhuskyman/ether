# Каналы, большие группы, поиск, админ-инструменты (V.80)

## Каналы
- Владелец создаёт пару ECDSA P-256 канала (закрытый ключ хранится только у него). Ссылка `#ch=<id>.<хеш ключа>[.<ключ канала>]`: подписчик закрепляет хеш открытого ключа; сервер отдаёт ключ при подписке, несовпадение отвергается.
- Каждый пост и мета подписаны владельцем. Сервер проверяет подпись (отсекает чужие посты) и клиент проверяет повторно: сервер не может подделать пост. Ошибка подписи — пост скрыт, в чате баннер.
- Закрытый канал: тела постов шифруются AES-256-GCM ключом канала, который лежит во фрагменте ссылки (не уходит на сервер). Доставка ключа подписчику = сама ссылка/QR. Смена ключа (kv+1) = новая ссылка.
- Сервер (`signaling-server/channels.js`): `channel-create/-info/-subscribe/-unsubscribe/-post/-history/-meta/-delete`; кольцо истории `CHANNEL_HISTORY_MAX` (200), TTL `CHANNEL_POST_TTL_DAYS` (30), лимит подписчиков `CHANNEL_SUBS_MAX` (5000), размеры, частота; офлайн-подписчикам Web Push без содержимого, историю они забирают при подключении. Хранилище `DATA_DIR/.ether-channels.json` (0600, атомарная запись). Сервер видит, кто подписан (метаданные), но не ключ закрытого канала.
- Старые клиенты не знают `channel-*` и не получают их (сервер шлёт только подписчикам).

## Sender Keys
- `js/groupkeys.js`: цепочка отправителя (ck, ECDSA-подпись), раздаётся по 1:1 E2E (`gk-dist`), храповик HMAC, окно пропусков 256. Rekey при исключении (лениво, перед следующей отправкой), текущая цепочка — новичку, запрос ключа `gk-req`.
- `gdeliver` (`signaling-server/gdeliver.js`): один конверт, fan-out онлайн + ящик (kind `gchat`). Реестр групп на сервере (`group-roster`, `GROUP_MAX_MEMBERS` 256); получатели = пересечение со списком отправителя. Режим включается при >8 участниках и `sk1` у всех. Квитанции доставки/прочтения для таких сообщений не рассылаются. Файлы/реакции/правки остаются попарными.

## Роли и админ-инструменты
- owner > admin > moderator > member. Все действия (`group-admin`) подписаны ключом личности автора и проверяются получателем по матрице `GroupAdmin.can` (`js/groupadmin.js`); seq предотвращает повтор. Ростер не повышает роли (только владелец назначает admin; moderator — только подписанным действием).
- Кик/бан с причиной, медленный режим, «только объявления», политика закрепления, одобрение входа, ссылка со сроком (подписана приглашающим), передача владения. Интерфейс — в блоке «Дополнительно» сведений о группе.

## Локальный поиск
- `js/search.js`: инвертированный индекс в памяти, строится при запуске порциями, не сохраняется. Фразы в кавычках, префиксы, ru/en/ar, операторы `in: from: type: after: before:`.
