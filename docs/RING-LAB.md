# Ring Lab (V.80.1): что делать на iPhone и как читать результат

Вход один: вкладка **Отладка → Ring Lab** (если вкладки нет — 5 касаний по шапке). Ничего из экспериментов не включено в реальные звонки само. Честно: без настоящего iPhone эти механизмы проверить нельзя — лаборатория лишь помогает вам снять результат и выгрузить его текстом (кнопки «Копировать журнал», «Скачать .txt», «Отправить»). Журнал хранится только в `localStorage` этого устройства.

Мастер «Сделай чтобы звонило» (кнопка вверху лаборатории): Уведомления → «Допуск»/«Звуки»/«Экран блокировки»/«Баннеры», список разрешённых приложений в Фокусировании, переключатель «Звонок/Бесшумно» (в «Бесшумно» молчат и уведомления, и обычные звонки; громко звучат только будильники и «Экстренный обход»), «Экстренный обход» для контакта в «Контактах» iPhone (для громкого iMessage/звонка телефона), затем самопроверка пуш-звонком (3 «гудка» с сервера).

## Эксперименты (у каждого: Запустить / PASS / FAIL / Заметка)
1. **Обычный пуш-звонок (raw)** — формат V.79. PASS: уведомление «звонит» пришло при заблокированном экране. FAIL при «разрешено, подписка есть» — это ограничение iOS/Фокуса/«Бесшумно», а не приложения.
2. **Гибридный (declarative, mutable:true)** — тот же ряд «гудков» в формате Declarative Web Push (`web_push:8030`, `mutable:true`, `data.t="call-ring"`). Если SW жив — работает ack/дедуп как у raw; если нет — iOS показывает уведомление сама (ack тогда не будет, звонящий не увидит «звонит»). Сравните с №1: приходит ли быстрее/надёжнее, есть ли ack («Пуш дошёл за N с»). На сервере по умолчанию выключено (`PUSH_RING_HYBRID=1` включает для реальных звонков).
3. **Режим ожидания** — тихий циклический звук + Media Session «Ожидание звонка» + сторож (время жизни, состояние сокета, число «заморозок»). Сверните приложение и отправьте тест-звонок (№1 с другого устройства или сразу после сворачивания): при живой странице играет рингтон приложения. PASS — рингтон слышен при свёрнутом приложении. Сильно расходует батарею; iOS может остановить страницу в любой момент (счётчик пауз это покажет). Есть опт-ин «включать при запуске» (стартует после первого касания — автоплей без жеста запрещён).
4. **Громкая ссылка (iMessage/SMS)** — создаётся ссылка-звонок и открывается `sms:` с готовым текстом. PASS — сообщение пришло с громким сигналом. Номер берётся из локального поля контакта.
5. **Ссылка FaceTime (эксперимент)** — открывается сохранённая у контакта `https://facetime.apple.com/join#…`. Поведение не гарантируется Apple.
6. **Аудиосессия и AudioContext** — `navigator.audioSession.type`, состояние `AudioContext`. Если тон слышен только при «Звонок», а при «Бесшумно» нет — Web Audio глушится переключателем.
7. **Уведомления** — разрешение, service worker, подписка.
8. **Календарь (.ics)** — файл с тестовым звонком на +8 минут (ссылка-звонок живёт ~10 минут) и будильниками за 5 минут и в момент звонка. PASS — сигнал календаря прозвучал (проверьте и при «Бесшумно»).
9. **Отчёт об устройстве** — версия iOS, режим «Домой», поддержка push и признак declarative push (`window.pushManager`, признак — не гарантия).

## Микрофон в фоне
Петля внутри страницы (микрофон → RTCPeerConnection → приём; в наушниках, иначе эхо). Запустите вариант, сверните приложение на 15–30 с, шумите рядом, вернитесь, нажмите «Закончить»: отчёт покажет, шёл ли звук в фоне (`totalSamplesReceived`, `totalAudioEnergy`), события трека `mute/unmute/ended`, смены видимости, число автовосстановлений. Если таймеры в фоне заморожены, вывод строится по замерам до сворачивания и после возврата (пометка `timers-frozen`).
Варианты: 1 базовый; 2 + `audioSession=play-and-record` + Media Session (`setMicrophoneActive`) + реальное воспроизведение удалённого звука; 3 + Picture-in-Picture (видеозвонок: удалённое `<video>` с `autoPictureInPicture` и кнопка; аудиозвонок: canvas с аватаром и таймером + аудиотрек удалённого потока → `captureStream()` → `<video>` → PiP); 4 + Screen Wake Lock; 5 PiP с беззвучным видео. Галочка «Автовосстановление»: при `mute/ended` и возврате в приложение — повторный `getUserMedia` и `RTCRtpSender.replaceTrack` (в реальных звонках собеседнику при этом уходит существующий сигнал «микрофон приостановлен»).
Интерпретация: «audio flowed while hidden» + PASS в нескольких запусках — вариант стоит дальше изучать; «NO audio» — iOS остановила захват (ожидаемо). Если вариант заработал, он остаётся ТОЛЬКО переключателем «Помощь в звонках» (audioSession + Media Session + Wake Lock; по умолчанию выкл.), PiP-варианты в звонки не подключены.

## Прочие переключатели (по умолчанию выкл.)
- «Помощь в звонках» — см. выше. 
- «Через 12 с без “звонит у собеседника” предлагать Позвонить громко» — внутренний хук исходящего звонка; открывает тот же лист, что и эксперимент 4/5. На экран звонка ничего постоянно не добавляется.
- Поля контакта «Телефон» и «Ссылка FaceTime» задаются здесь же (выбор из Контактов — только где есть Contact Picker, на iPhone Safari его нет). Хранятся только в записи контакта на устройстве, на сервер не отправляются, в push и сообщения не попадают.

## Что изменилось в push (A, B)
- Сообщения теперь `mutable:true` с `lang`, `dir`, `silent:false`, `timestamp`; `app_badge` не шлётся (сервер не знает общего числа непрочитанных). Заблокированный контакт: если SW жив, он ничего не показывает и закрывает `event.notification`; если SW мёртв, сервер блок-лист не знает — уведомление покажет платформа (так было и раньше при `mutable:false`).
- Гибридные «гудки» и отмена (`call-cancel` с тем же tag `ring-<callId>`, текст «Звонок завершён/Пропущенный звонок» на языке подписки: сейчас en/ru, остальные — en) включаются `PUSH_RING_HYBRID=1` или `push-test-ring` с `mode:"hybrid"`.
