Как это работает

Сообщения и звук — всегда напрямую. Они идут между устройствами по протоколу WebRTC. Ни текст, ни голос никогда не проходят через сторонний сервер и не сохраняются нигде, кроме ваших устройств.

Сигнальный сервер нужен только для рандеву. Он в реальном времени хранит в памяти (не на диске) короткий список «кто сейчас онлайн» — по хэшу от номера/email, не по самому номеру — и один раз пересылает технический пакет подключения (offer/answer), когда оба контакта одновременно в сети. Дальше сервер из разговора выходит полностью, даже если позже вы позвоните ещё раз.

Можно и совсем без сервера. В разделе «Контакты» есть режим «Ручное подключение по коду» — тогда вы сами пересылаете код любым способом, а сервер не участвует вообще, даже в рандеву.

Публичные STUN-серверы Google помогают устройству узнать свой внешний сетевой адрес — как справочная служба, которая называет номер, но не слушает разговор.

Ограничения: оба человека должны иметь открытое приложение (хотя бы в фоне на компьютере, на телефоне — активным) в момент установления связи. Push-уведомлений о сообщении, когда приложение полностью закрыто, всё ещё нет — это отдельная большая тема. Свой сигнальный сервер нужно один раз развернуть — инструкция в README проекта.
