Connection server
Privacy

Contacts see when you were last online. Turn off to hide it (you also won't see theirs).

Contacts see a green dot when the app is open.

Off by default. When on, the server stores only a salted hash of your number/email, your id and public key. Tap the switch to read the details.

These are symmetric: if you turn one off, you also stop seeing that information from your contacts.

Before calling (or answering) a contact you have not verified with a safety number or QR, the app will ask you to verify first. A changed key always blocks calls until confirmed.

Calls go only through a relay server, so the other side never sees your IP address. Tradeoff: lower quality and more delay. Applies to new connections.

After a call, shows a short summary of how it went. Data stays on this device; you can export it as JSON.

Notifications show only the sender's name, not the message text.

To show a preview, the signaling server briefly fetches the link on your behalf — it sees which link, not the message.

Translation server

Empty by default — translating a message sends its text in the open to this server, so pick one you trust. Without one set, "Translate" in a message's menu just explains that.

From – to

At these hours messages arrive without sound or vibration. Calls still ring.

Messages, keys and files are stored encrypted with a key made from your PIN (6+ digits). Protects against someone copying the device storage. If you forget the PIN, the data cannot be recovered. A short digit PIN can still be guessed offline — use a long one.

Local AI

Recognition runs on this device — audio is never sent anywhere. The first use downloads a ~40 MB model from huggingface.co and the engine from jsdelivr.net (those servers see your IP address). The model is cached afterwards.

Backup

The Messenger has no server backup — everything lives only on this device. If you lose or replace this device, contacts, groups and messages are gone unless you save a backup file yourself.

Danger zone

Best-effort, not a guaranteed silent trigger — a sharp shake (e.g. someone grabbing your phone) shows a brief cancellable warning, then wipes this device if not cancelled. False positives are possible; test it before relying on it.

Permanently erases contacts, messages and keys from this device. There is no server copy to restore from — make a backup first if you want one.

    Find by phone/email
    
    
    Enter phone numbers (with country code) or emails of people you know. Your app turns each into a salted hash and asks the server which hashes were published by people who chose to be found. The server never sees the numbers you search for, only hashes; people who did not opt in look the same as people who are not here. Limits apply (20 searches per hour).
    
    
    Honest warning: phone numbers can be guessed. The salt and rate limits make mass guessing slow, not impossible. That is why this is opt-in.

    Host your own server
    
    
    The Messenger's signaling server never sees message content — only who's online and brief routing metadata (and, for file previews, a fetched link). Running your own gives full control over that metadata, useful for firms, clinics or teams that need "the vendor can't see our traffic" in writing.
    
    
    cd signaling-server && cp .env.example .env && docker compose up -d
    
    
    1) Edit .env with your VAPID keys (npm run generate-vapid) and domain. 2) Deploy behind HTTPS/WSS (a reverse proxy like Caddy or nginx works well). 3) Paste your wss:// URL into "Signaling server" above.
    
    
    Full steps, env variables and a sample compose file are in signaling-server/SELF_HOSTING.md in the The Messenger repository.
